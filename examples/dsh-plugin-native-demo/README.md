# dsh-plugin-native-demo

官方示例插件：一个**第三方插件**，建立在 Fish Pocket 提供的本机能力之上。

它的存在是为了被跑起来，不只是被读。装上它就验证了设计里那个核心主张
（[`docs/native-services.md`](../../docs/native-services.md) §4.1）：

> 系统授权给了之后，引擎本体和第三方插件直接可用，应用层不再设授权门。

这个插件没有第二次授权，也没有任何特权通道。它向容器要 `iosNative`，拿到的
和智能体自己的工具拿到的**完全一样**——不多也不少。

## 两个工具

| 工具 | 回答的问题 |
|---|---|
| `daily_briefing` | 这东西有用吗？读手机状态 + 今天的日程，可以念出来 |
| `native_check` | 边界还在吗？列出本机能力，并验证没实现的操作确实被拒 |

`native_check` 是 §9.3 那条教训的产品化：它去调两个**不存在**的东西——
`calendar.wipe`（能力在、操作不在）和 `healthkit.read`（能力根本不在）——
然后报告有没有被拦住。两条都该被拒；任何一条通过了都是 bug。

## 装上它

插件安装支持 npm 包名、Git 地址、tarball 和**绝对本地路径**。这个包在仓库的
子目录里，没发到 npm，所以走本地路径最省事：

1. 让智能体把仓库拉到它自己的工作区（引擎自带 git）：

   > 把 https://github.com/imsai-sh/fish-pocket 克隆到当前目录

2. 让它告诉你插件目录的绝对路径：

   > `examples/dsh-plugin-native-demo` 的绝对路径是什么

3. 设置 → 插件 → 安装，把那个路径粘进去。

装完要重启引擎（安装操作本来就会提示）。

> **为什么不能自己拷文件进去：** App 的文档目录没有对「文件」App 开放，所以
> 手机上没有别的途径把文件放到引擎能读到的地方。让智能体去 clone 是目前唯一
> 不需要先发包的装法。

## 跑一遍该看到什么

装好之后跟智能体说：

> 我今天怎么样

第一次会弹系统的日历授权弹窗（如果还没授权过）。然后：

> 检查一下本机能力

`native_check` 应该报告两条都被拒：

```
calendar.wipe   → refused (capability 'calendar' has no operation 'wipe')
healthkit.read  → refused (unknown capability 'healthkit')
```

最后去**设置 → 本机能力 → 使用记录**。你会看到刚才那次日历读取，
**调用方写的是 `dsh-plugin-native-demo`，不是「智能体」**。

这正是整套设计要你看见的东西：插件和本体走同一条路、拿同样的权限，
区别只在事后那一行记录里——而那一行也只是插件自报的名字，不是证据。
